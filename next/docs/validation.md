# 验证设计

## P0 已有检查

`gmd_next.operators` 检查重复索引累加、提取—装配伴随恒等式、空关系和越界。
`gmd_next.lj` 检查解析双粒子参考、有限差分力、能量形变导数得到的维里、
半表/全表计数、边方向与顺序、原子重编号、周期平移、两种截断、排除和错误输入。

参考函数是纯主机计算。显式半表由调用方提供，未包含邻居构建或时间推进。
这些检查不重现预印本中缺失的 Python 脚本，也不将新增数值结果归为论文原结果。

## 证据层次

1. 数学契约：伴随、计数、排列不变性和内部作用的总力。
2. 独立物理参考：解析双体值、能量有限差分、形变导数，避免仅复用力公式。
3. 新 CPU/GPU 对照：相同坐标、参数、单位、关系和截止模式。
4. 旧 GMD 行为对照：通过文件/快照适配，不链接旧引擎。
5. 已核验的外部引擎参考：保留来源、版本、常数、函数形式与容差依据。

旧 `validation/` 的数据可以作为候选输入；使用前检查每个 case 的真实
来源，区分解析、外部引擎与内部 regression baseline，不能统称外部真值。

## 后续正确性矩阵

| 范围 | 必测情形 |
|---|---|
| 数值 | NaN/Inf、空输入、重合、退化角、接近 cutoff、精度与归约变化 |
| 关系 | 半/全表、重复/缺边、排除/缩放、参数类型、容量不足和重算 |
| 周期 | 三轴跨界、角落、连续多次穿盒、更新镜像、重排后邻居有效性 |
| 积分 | F0、新位置上的力、步长收敛、漂移、restart、输出时点 |
| CUDA | stream 顺序、workspace 冲突、扩容后的旧 view、异步错误、设备选择 |
| 多设备 | owned/ghost、空分区、迁移、反向力、EAM 聚合、全局计数 |
| 扩展物理 | PME 归一化/自能/净电荷修正、约束秩与 DOF、完整维里、变盒失效 |

误差形式采用 `abs_error <= atol + rtol * abs(reference)`，并报告 max/RMS。
按物理量、精度、规模及参考方法确定阈值。接近零的量必须有绝对容差；不得
按观察误差随意放宽。长期 NVE 增加多步长研究，不能只比一帧。

## 性能记录

先通过正确性，再报告单独的 kernel、力计算和端到端步耗时。
记录 GPU/SM、驱动/Toolkit、编译器与 flags、精度、原子/边数、势模型、
cutoff/skin、重建频率、输出频率、设备数和 warm-up；使用正确同步的计时。
明确是否包括上传、下载、重建、通信和 I/O，同时记录峰值显存及扩容次数。
CPU 参考实现用于判定语义，不作为生产 CPU 性能基准。

## 隔离验收

在新临时目录复制 `next/` 后独立 configure/build/test；不需要父目录头文件、
CMake 模块或库。父项目文件的内容应与搭建前一致。CUDA 开启而无工具链时
必须清楚失败，不能静默将 CUDA 请求降级为 CPU。
