# 实施计划与状态

先完整设计依赖与所有权，再按功能切片实现。完成一个阶段不意味着后续
能力已存在；性能改动必须保持已确定的物理模型。

具体目录、构建目标、数据接口、任务依赖及验收见[程序实施规划](program_plan.md)。
首个可交付版本 R1 限定单 GPU、FP64、固定正交周期盒、单类型 LJ、NVE、
轻量轨迹/日志与经过验证的重启功能。P2d 异步优化按实测需要引入，不阻塞 R1。
性能记录从 P1 的静态 GPU 力计算开始，随后覆盖完整步，不等到 P6 才测量。

| 阶段 | 交付 | 验收条件 | 当前状态 |
|---|---|---|---|
| P0 | 独立构建、设计文档、CPU Gather/装配/LJ、CUDA/CUB 探针 | CPU 检查与独立复制构建通过；CUDA 在目标机另验 | 已搭建；CUDA 待目标机验证 |
| P1 | DeviceState、stream/workspace、显式半表 GPU LJ、输出结果契约 | FP64 的 U/F/W 与独立参考、CPU 契约一致；快照标明单位/时间层/有效性；无静默回退 | P1.1 主机契约已实现（CPU 验证）；P1.2 代码已写，未经 nvcc 编译、未在 GPU 运行；P1.3–P1.5 未实现 |
| P2 | GPU 邻居关系、固定盒 NVE、轻量输出与共同范围的 checkpoint（分 P2a–P2d） | 动力学、文件兼容及续跑分别验收；同步输出先行，异步收益实测 | 未实现 |
| P3 | EAM 密度/嵌入/力链，随后 bonded 超边与模型组合 | 有序索引、退化处理、多元素方向、分阶段依赖验证；解析例子与材料参数能力分开 | 未实现 |
| P4 | 多 GPU 分区、迁移、halo、反向装配 | 1/2/多设备与空分区；粒子身份、计数、跨域 EAM 正确 | 未实现 |
| P5 | cuFFT PME、约束及热浴/压浴 | 各自独立参考、约束秩/收敛、维里/DOF/盒变化与 restart 验证 | 未实现 |
| P6 | 性能与发布收敛 | 端到端性能、内存、强弱扩展、运行信息与覆盖边界可复现 | 未实现 |

## 可提前设计、不可冒称已完成

P1 就预留 ID、owned/ghost、设备身份与 completion 的语义，但不需要先完成
多 GPU 传输。P2 的图有效性包含盒版本，但首版仍限定固定正交盒。P3 的
节点聚合要求提前明确，而不是等到实现 EAM 时才发现装配接口只能处理二体。

## 与当前 GMD 的关系

- 现有源码、默认构建、测试和基线保持独立。
- 模型输入和参考数据通过显式转换复用，不迁移旧内部类。
- 基础算子及积分结果经按需记录直接进入独立序列化层，保留现有文件格式与
  旧 API 兼容入口；具体边界见[架构第 7 节](architecture.md#7-与现有输出接口相接)。
  旧 `System` 桥接只作可选过渡工具，不引入 `next/` 核心对旧引擎的依赖。
- 先比较静态 U/F/W，再比较单步与短时轨迹；长期动力学比较统计与漂移，
  不要求混沌轨迹永久逐位重合。
- 只有覆盖范围、验证与使用入口达到预定要求后，另行讨论默认引擎切换。
  本次搭建不改变默认程序。

## 输出接入的阶段验收

除 P1 的主机请求契约外均未实现；[输出层设计](output_pipeline.md)定义具体契约与成本指标。

| 子阶段 | 交付与验收 | 性能要求 |
|---|---|---|
| P1 | 输出订阅、字段/时间层契约及稳定 ID；不将 CPU `PairResult` 当作设备 ABI（主机侧 `ObservableRequest`/`ObservableRecord`、`AtomId`、版本与采样阶段已实现；订阅频率与设备结果未实现） | 明确动力学必需量与仅输出所需量 |
| P2a | 固定盒 GPU NVE 与邻居关系；独立完成跨盒、skin、容量及能量行为检查 | 建立关闭输出的完整时间步基线 |
| P2b | 同步轻量记录、共享序列化核心、旧 API 兼容包装；XYZ/日志可独立频率 | 标量日志不下载原子数组；轨迹不构造旧 `System`；缓存静态元数据 |
| P2c | 共同 NVE 范围的 checkpoint 写入、读回、续跑及失败提交处理 | 单独报告完整状态捕获与文件写入成本 |
| P2d | 按实测瓶颈引入独立设备打包、有界主机缓冲池及异步消费者 | 与 P2b 同负载比较，包含队列等待及最终排空；无收益时保留同步路径 |

P2b 可先用外围旧 `System` 桥接做文件对照，但这不算轻量输出优化已完成。
提取格式代码时，旧默认联合输出行为和文件字段须有回归验证；独立频率模式
额外验证按 step/time 关联的消费者。记录正确性与物理推进正确性分别检查。

P4 增加跨设备排序、迁移、owned/ghost、全局归约及旧 ID 范围限制的检查；
P5 增加约束、热浴/压浴的状态与时间层兼容性，避免提前承诺全功能互通。
