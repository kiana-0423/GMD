# 实施计划与状态

先完整设计依赖与所有权，再按功能切片实现。完成一个阶段不意味着后续
能力已存在；性能改动必须保持已确定的物理模型。

| 阶段 | 交付 | 验收条件 | 当前状态 |
|---|---|---|---|
| P0 | 独立构建、设计文档、CPU Gather/装配/LJ、CUDA/CUB 探针 | CPU 检查与独立复制构建通过；CUDA 在目标机另验 | 已搭建；CUDA 待目标机验证 |
| P1 | DeviceState、stream/workspace、显式半表 GPU LJ | FP64 的 U/F/W 与独立参考、CPU 契约一致；无静默回退 | 未实现 |
| P2 | GPU cell/邻居关系、固定盒、Velocity Verlet NVE | 跨盒/skin/容量测试，长期能量与步长收敛；热路径设备常驻 | 未实现 |
| P3 | bonded 超边与 EAM 密度/嵌入/力链 | 有序索引、退化处理、多元素方向、分阶段依赖验证 | 未实现 |
| P4 | 多 GPU 分区、迁移、halo、反向装配 | 1/2/多设备与空分区；粒子身份、计数、跨域 EAM 正确 | 未实现 |
| P5 | cuFFT PME、约束及热浴/压浴 | 各自独立参考、约束秩/收敛、维里/DOF/盒变化与 restart 验证 | 未实现 |
| P6 | 性能与发布收敛 | 端到端性能、内存、强弱扩展、运行信息与覆盖边界可复现 | 未实现 |

## 下一次实现从 P1 开始

1. 在目标 CUDA 开发机编译运行探针，记录 GPU、SM、驱动、Toolkit 与编译器。
2. 实现设备缓冲区所有者、view 与一个显式执行上下文；验证生命周期和错误传播。
3. 定义主机输入快照的上传/下载边界；设备状态带稳定 ID，关系使用本地索引。
4. 先上传显式小型半表，在一个融合 kernel 中计算 LJ 局部贡献并装配力；
   能量和九分量维里经归约输出。
5. 对 P0 的固定构型、边反向、排除及 cutoff 两种模式作 CPU/GPU 对照，
   再扩展随机非退化构型和极端规模。性能不是此阶段通过正确性的替代条件。

## 可提前设计、不可冒称已完成

P1 就预留 ID、owned/ghost、设备身份与 completion 的语义，但不需要先完成
多 GPU 传输。P2 的图有效性包含盒版本，但首版仍限定固定正交盒。P3 的
节点聚合要求提前明确，而不是等到实现 EAM 时才发现装配接口只能处理二体。

## 与当前 GMD 的关系

- 现有源码、默认构建、测试和基线保持独立。
- 模型输入和参考数据通过显式转换复用，不迁移旧内部类。
- 先比较静态 U/F/W，再比较单步与短时轨迹；长期动力学比较统计与漂移，
  不要求混沌轨迹永久逐位重合。
- 只有覆盖范围、验证与使用入口达到预定要求后，另行讨论默认引擎切换。
  本次搭建不改变默认程序。
